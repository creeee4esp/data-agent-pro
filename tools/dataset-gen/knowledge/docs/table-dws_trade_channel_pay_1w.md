# 表说明：dws_trade_channel_pay_1w（DWS-支付渠道粒度支付汇总（周））

## 概述

`dws_trade_channel_pay_1w` 把支付明细按周、按渠道汇成一行，当前 212 行，`stat_date` 存的是每周的周一日期。跟你解释一下口径：数据从 `dwd_trade_pay_di` 来，`pay_cnt` 是支付记录条数，`pay_amt` 是金额求和，而且是按支付日期归属的——这点要记牢，它和按下单日期算的那套指标不是一回事，混着用会对不上账。

## 字段

- `stat_date`：统计周，取周一日期，想查某一周就拿那周周一的日期去匹配，跨周取数用它排序或 `BETWEEN`。
- `pay_channel`：支付渠道，和 `stat_date` 一起决定一行，同一周同一渠道只会出现一次。
- `pay_cnt`：支付笔数，是当周该渠道的支付记录条数，周与周之间可以相加。
- `pay_amt`：支付金额（元），当周该渠道的金额合计，同样可以跨周累加。

## 上下游

来源是支付明细表 `dwd_trade_pay_di`，加工时按周一日期和 `pay_channel` 分组聚合写入本表，目前没有下游表。要出更粗的汇总，一般直接在本表上再聚合。

## 使用注意

想看渠道的周走势、周区间的支付笔数和金额、或者周维度的渠道占比，用这张表正合适。但别拿它去查某一天，日粒度请用日表；跨月对比用月表更顺手。还得提醒你留意同家族的一堆噪声表：历史归档 `dws_trade_channel_pay_1w_his`、备份 `dws_trade_channel_pay_1w_bak`、带日期备份 `dws_trade_channel_pay_1w_bak_20250219`、测试表 `test_dws_trade_channel_pay_1w`。这些要么是老数据归档、要么是备份快照、要么是调试用的，数据未必准，做统计时千万认准本表，别图省事取到它们上面。
