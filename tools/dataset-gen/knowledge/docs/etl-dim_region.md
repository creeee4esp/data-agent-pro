# 加工说明：dim_region

## 加工逻辑

`dim_region` 是 DIM-省份与大区维表，当前 16 行，一条记录对应一个省份到大区的映射。它解决的是"把省份归到华东、华南这些大区"的查表问题，下游要算区域维度时，拿省份来关联就能拿到大区。

加工分两步想。先把省份清单凑齐：从用户表 `ods_user_info_di` 取 `province`，再从订单表 `ods_trade_order_di` 取 `receiver_province`，两者用 `UNION` 合并去重，得到一份完整的省份名单。再用一个 `CASE` 把每个省份映射成大区，比如上海市、江苏省、浙江省、安徽省、山东省归"华东"，广东省、福建省归"华南"，北京市、天津市、河北省归"华北"，湖北省、湖南省、河南省归"华中"，四川省、重庆市归"西南"，陕西省归"西北"，没命中的落到"其他"。

```sql
SELECT p, CASE p WHEN '上海市' THEN '华东' ... WHEN '陕西省' THEN '西北' ELSE '其他' END
FROM (SELECT DISTINCT province AS p FROM ods_user_info_di
  UNION SELECT DISTINCT receiver_province FROM ods_trade_order_di) t
```

跟新同事提一句：省份来源同时覆盖用户注册省和订单收货省，所以哪怕某个省只在收货地出现过，也能在这张表里查到它的大区。

## 依赖与调度

`dim_region` 依赖两张上游表：订单表 `ods_trade_order_di` 和用户表 `ods_user_info_di`。调度每天 02:00 开始，等上游全部成功后才运行，处理前一天（T-1）的数据。

## 质量检查

`dim_region` 发布前要过三项检查：主键 / 粒度唯一，保证一个省份只有一行；关键字段非空；行数与前一天相比波动超过 30% 告警。

这几项挂了会连累下游。省份粒度重复，下游按省份关联大区时会一对多膨胀，区域汇总被重复累加；大区字段为空，部分省份算不进任何大区；行数骤降往往是上游省份没抽全，一些省份关联不到大区就落了空。看到告警先把上游确认清楚再发布。
