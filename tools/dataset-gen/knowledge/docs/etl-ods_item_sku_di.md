# 加工说明：ods_item_sku_di

## 加工逻辑

`ods_item_sku_di` 存 ODS-商品SKU表，当前 300 行，是业务源表 `item_sku` 的贴源落地。加工整表原样同步，不清洗不聚合，只在源表全部字段后追加固定 ETL 时间列和分区列 `dt`。

```sql
INSERT INTO ods_item_sku_di SELECT item_sku.*, <固定 etl_time>, <分区 dt> FROM item_sku
```

有个容易误用的地方要点一下：这是贴源表，品牌和品类还没拼全。下游 `dim_sku` 才把它和品牌表、品类表关联、补上 `brand_id`、两级品类等属性。要按品牌或品类分析商品，应该用 `dim_sku`，直接在这张表上做关联容易漏属性。

## 依赖与调度

`ods_item_sku_di` 依赖一张上游表，业务源表 `item_sku`。调度每日 01:00 开始，依赖上游全部成功后运行，处理前一天（T-1）的数据。作为 ODS 层任务，它跑在 `dim_sku` 等下游前面。

## 质量检查

`ods_item_sku_di` 发布前跑三项检查：主键 / 粒度唯一，保证 SKU 不重复；关键字段非空；行数与前一天相比波动超过 30% 告警。

检查失败会往下游传。SKU 重复会让 `dim_sku` 以及按商品关联的明细表膨胀，销量金额被重复计算；关键字段为空会让下游商品属性缺失；行数骤降往往是源表 `item_sku` 没抽全，部分商品在下游关联不上。看到告警先核查源表再发布。
