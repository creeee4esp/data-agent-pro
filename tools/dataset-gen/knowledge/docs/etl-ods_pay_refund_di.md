# 加工说明：ods_pay_refund_di

## 加工逻辑

`ods_pay_refund_di`（ODS-退款单表）直接映射业务库的 `pay_refund`，不做任何聚合或清洗，只把源表全列原样抽取过来，并补上加工时间戳 `etl_time` 和分区字段 `dt`。核心加工语句如下：

```sql
INSERT INTO ods_pay_refund_di
SELECT pay_refund.*, <固定 etl_time>, <分区 dt>
FROM pay_refund
```

这里有一处容易误用：`pay_refund.*` 是跟随源表结构的，一旦上游 `pay_refund` 增删字段，`ods_pay_refund_di` 的列也会随之变化，下游如果按位置取列而不是按列名取列，很容易错位。另一处要注意的是 `etl_time` 是本次加工写入的固定时间，并不是业务上的退款发生时间，统计退款时间请用源表自带的时间字段，别拿 `etl_time` 当业务时间用。当前产出约 1,031 行。

## 依赖与调度

`ods_pay_refund_di` 只有一个上游依赖，即业务库退款单表 `pay_refund`。调度上每日 01:00 开始，依赖上游全部成功后才运行，处理前一天（T-1）的数据，写入当天对应的 `dt` 分区。

## 质量检查

`ods_pay_refund_di` 落地后会跑三项检查：主键 / 粒度唯一、关键字段非空、以及行数与前一天相比波动超过 30% 告警。退款单量本身波动较大，30% 的阈值告警后需要人工判断是真实业务波动还是抽取异常，不要直接当故障处理。任何一项检查不通过，都会阻断或污染所有以 `ods_pay_refund_di` 为源的下游退款相关表，导致退款口径的数据缺失或失真。
