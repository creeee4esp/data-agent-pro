# 表说明：dws_trade_brand_order_1m（DWS-品牌粒度下单汇总（月））

## 概述

`dws_trade_brand_order_1m` 是品牌维度的下单月汇总表，目前只有 144 行，数据量很小，适合直接查看。它把每个自然月、每个品牌的下单情况各压成一行，`stat_date` 存的是这个月的月初日期，而不是具体某一天，刚接手的同事常常误以为它是日表，这里要先提醒一句。数据由交易明细按月聚合而来，口径和日表、周表保持一致，只是统计周期不同。

## 字段

- `stat_date`：统计月，取值是每个月的月初日期（如某月的 01 号），它代表整月而非当天，筛选某个月时记得用月初日期去匹配。
- `brand_name`：品牌名称，和 `stat_date` 一起决定一行，同一个月同一个品牌只会出现一次。
- `order_cnt`：下单数，是该品牌当月去重后的订单计数，月与月之间可以相加。
- `item_qty`：购买件数，包含了未支付订单的件数，看销量时要记得这个口径偏大。
- `paid_amount`：已支付订单的明细金额（元），只算已支付的那部分，别把它当成全月下单总额。

## 上下游

来源是交易明细表 `dwd_trade_order_detail_di`，加工时按月初日期和 `brand_name` 分组求和写入本表，目前没有登记下游表。想做更高层的汇总时，通常直接在本表上再聚合即可。

## 使用注意

想看品牌的月度走势、做月度同比环比、或者按品牌排月度已支付金额榜，用这张表最省事，一个月一行，查起来很快。但如果要看某一天或某一周的情况，就别用它了，请改用日表或周表。另外要当心同名的备份：库里有一张 `dws_trade_brand_order_1m_bak`，还有 6 张带日期的备份（如 `dws_trade_brand_order_1m_bak_20250215`、`dws_trade_brand_order_1m_bak_20250225`），这些都是某次操作前留下的历史快照，数据未必是最新的，做统计时一律认准本表，不要图方便拿备份表凑数。
