# 指标说明：支付订单数（paid_order_cnt）

## 计算公式

`paid_order_cnt` 统计的是已支付订单的笔数，口径是 `COUNT(DISTINCT IF(is_paid = 1, order_id, NULL))`。拆开看就是：只挑出 `is_paid = 1` 的已支付明细行，取它们的 `order_id` 去重计数，未支付的行会被置成 NULL 而不参与计数。因为一个订单在明细里会拆成多行，必须按 `order_id` 去重，不能数行数。时间归属看下单日期 `order_date`，哪天下单就归到哪天。由于是去重计数，这个指标不可加和，跨天相加会把同一订单在不同天的去重结果机械叠加，要算更长周期得回到明细重新去重。

## 取哪张表

按统计周期和维度选表是取数的第一步。用户维度的日粒度可以用 `dws_trade_user_order_1d`。若要看整体的支付订单数，日度看报表 `ads_trade_gmv_daily`，月度看 `ads_trade_gmv_monthly`，退款率月报 `ads_trade_refund_rate_monthly` 里也会用到它作为分母。按维度和周期对齐着选，不要用日表自己加总去凑月度去重数。

## 来源与历史变化

数据一路追到明细就是下单明细表 `dwd_trade_order_detail_di`，上面的汇总表和报表都是在它之上按维度聚合出来的。这个指标自上线以来未调整计算规则，去重口径一直没变，历史数据和当前数据可以放心做趋势对比。
