# 表说明：dws_trade_user_pay_1d（DWS-买家用户粒度支付汇总（日））

## 概述

`dws_trade_user_pay_1d` 按统计日期和买家用户汇总每日支付，当前 17,293 行。跟你讲下口径：数据从支付明细 `dwd_trade_pay_di` 来，`pay_cnt` 是支付记录条数，`pay_amt` 是金额求和，而且按支付日期归属——和按下单日期算的下单类指标不是一套，别混着对账。

## 字段

- `stat_date`：统计日期，按天，想查某天用它等值过滤，查区间用 `BETWEEN`。
- `buyer_id`：买家用户ID，`bigint` 类型，和 `stat_date` 一起决定一行，是用户维度的主键。
- `pay_cnt`：支付笔数，当天该用户的支付记录条数，可以跨天相加。
- `pay_amt`：支付金额（元），当天该用户的金额合计，同样可以跨天累加。

## 上下游

来源是支付明细表 `dwd_trade_pay_di`，加工时按 `pay_date` 和 `buyer_id` 分组聚合写入本表，目前没有登记的下游表。需要更粗维度的支付汇总时，一般走对应维度的表。

## 使用注意

想看用户级的每日支付情况、活跃付费用户数（按 `buyer_id` 去重）、人均支付金额，用这张表很合适。要提醒的是，`buyer_id` 跨天不能直接相加去重，统计一段时间的活跃付费用户要用 `COUNT(DISTINCT buyer_id)` 重新去重。另外同家族里有几张噪声表：3 张带日期备份（如 `dws_trade_user_pay_1d_bak_20250519`、`dws_trade_user_pay_1d_bak_20251114`）和测试表 `test_dws_trade_user_pay_1d`。备份是历史快照、测试表是调试产物，数据未必准，做统计时认准本表，别取到它们上面。
