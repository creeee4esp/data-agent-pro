# 加工说明：ods_pay_order_di

## 加工逻辑

`ods_pay_order_di` 存 ODS-支付流水表，当前 18,031 行，是业务源表 `pay_order` 的贴源落地。加工整表原样同步，不清洗不聚合，只在源表全部字段后追加固定 ETL 时间列和分区列 `dt`。

```sql
INSERT INTO ods_pay_order_di SELECT pay_order.*, <固定 etl_time>, <分区 dt> FROM pay_order
```

有个容易误用的地方要点一下：这是支付流水，粒度是支付记录，不是订单。一个订单可能对应多条支付流水，拿它和订单数对比时别直接当成一一对应。要按渠道、省份看支付金额，用下游 `dwd_trade_pay_di`，那里已经关联订单表补上了收货省份。

## 依赖与调度

`ods_pay_order_di` 依赖一张上游表，业务源表 `pay_order`。调度每日 01:00 开始，依赖上游全部成功后运行，处理前一天（T-1）的数据。作为 ODS 层任务，它跑在下游各层前面。

## 质量检查

`ods_pay_order_di` 发布前跑三项检查：主键 / 粒度唯一，保证支付流水不重复；关键字段非空；行数与前一天相比波动超过 30% 告警。

检查失败会往下游传。流水重复会让 `dwd_trade_pay_di` 的支付笔数和金额翻倍，渠道金额算错；关键字段为空会让下游支付口径缺失；行数骤降往往是源表 `pay_order` 没抽全，支付金额偏低。看到告警先核查源表再发布。
